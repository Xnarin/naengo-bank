## 청킹
`python rag/chunk.py` → `data/rag/chunks.jsonl` (646청크, 중앙값 353자, 최대 1,055자) + 검토용 `data/rag/preview/*.md`

| 원천 | 단위 | 청크 |
|---|---|---|
| 법령 | 조 단위. 부칙과 기관 운영 장(예금보험공사 조직, 부실금융회사 정리, 업자 등록·허가·감독, 보칙)은 제외. 벌칙 장은 "통장 빌려주면 처벌받나요?" 같은 질문 때문에 포함. 800자 넘으면 항 → 호 순으로 나누고 머리말 `[법령명] 제N조(제목)`을 반복 | 469 |
| 약관 | 조 단위 + 전문 | 60 |
| 내금고 상품 | 상품 1개 (mock.ts) | 5 |
| 내금고 FAQ | Q·A 1쌍 | 43 |
| 착오송금 FAQ | Q·A 1쌍 | 12 |
| 용어 | 고객용 용어 36개만 (`GLOSSARY_KEEP`) | 36 |
| ~~finlife 상품~~ | 제외 (`chunk.py` SOURCES에서 주석 처리, 다시 넣으려면 주석만 풀면 됨) | 0 |

정제: 개정 이력 태그(`<개정 …>`) 제거, 삭제된 항·호 제거, 가운뎃점(ㆍ ․ ·) 통일.

각 행은 `{chunk_id: "파일#번호", text, metadata: {file_name, source_type, doc, article, title, effective_date, url, ...}}` 형식입니다.
`chunk_id`와 `file_name`은 이전 실습(rag-agent-practice)과 같은 형식이라 Hit@k, MRR 평가 코드를 그대로 쓸 수 있습니다.

법령 파일에는 frontmatter로 `시행일자`와 `출처`가 붙어 있어서, 답변할 때 근거로 인용할 수 있습니다.
청크는 `##### 제N조` 단위로 나누면 됩니다.

## 이 데이터로 답하는 질문 예시
- 예금자보호 한도는 얼마예요? → 예금자보호법 시행령 제18조 (1억원)
- 가입한 상품 청약철회 되나요? → 금융소비자보호법 제46조
- 모르는 사람이 이체했어요 / 보이스피싱 당했어요 → 통신사기피해환급법 제3조(피해구제 신청), 제4조(지급정지)
- 잘못 이체했어요, 해킹으로 돈이 빠져나갔어요 → 전자금융거래법 제8조(오류정정), 제9조(금융회사 책임)
- 다른 사람 명의로 통장 만들 수 있나요? → 금융실명법
- 계좌번호 잘못 눌러서 송금했어요 → 내금고 FAQ + 착오송금 FAQ (5만~1억원, 1년 이내 예금보험공사 신청)
- 통장 비밀번호 잊어버렸어요 / 통장 잃어버렸어요 → 예금거래기본약관 제13조(사고·변경사항의 신고), 제14조(통장, 카드의 재발급)
- 대출 연체하면 어떻게 돼요? / 기한이익 상실이 뭐예요? → 은행여신거래기본약관(가계용) 제3조(지연배상금), 제7조(기한전의 채무변제의무)
- 대출 미리 갚아도 돼요? → 같은 약관 제10조(기한전의 임의 상환)
- IRP가 뭐예요? → 금융용어해설

잔액, 거래내역, 송금, 금리처럼 자주 바뀌는 숫자는 RAG에 넣지 않고 기존 챗봇 의도(store 조회)나 finlife JSON 조회로 답합니다.

## 임베딩
`python rag/embed.py` → `data/rag/index/` (`vectors.npy` 646×3072, `chunks.jsonl` 행 순서 사본, `cache.npz` 본문 해시별 벡터 캐시)
- 모델 `gemini-embedding-2`, 키는 `.env`의 `GEMINI_API_KEY`. 문서는 `RETRIEVAL_DOCUMENT`, 질문은 `RETRIEVAL_QUERY`.
- chunk.py를 다시 돌려도 본문이 바뀐 청크만 새로 임베딩합니다.
- 검색 테스트: `python rag/embed.py "예금자보호 한도"` (코사인 상위 5개, numpy 전수 검색)
- 주의: SDK에 문자열 리스트를 넘기면 여러 텍스트가 벡터 1개로 합쳐집니다. 텍스트마다 `Content`로 감싸야 합니다.

## 골든셋과 평가
`data/rag/golden.csv`: 90문항 = 직접 작성 30(G) + 실제 질문 55(R, 아하. R45~R55는 빈 데이터를 채운 뒤 답변 가능해진 후보) + 답변 불가 5(U). 검색 DB(chunks)에는 넣지 않습니다.
- 열: `id, category, question, target_answer, evidence(근거 구절), targets("파일::조문 또는 FAQ 제목"; 여러 개면 ; 로), answerable(Y/N), coverage(full/partial), source, note`
- 정답은 chunk 번호가 아니라 파일+조문/제목으로 지정 → 청킹을 바꿔도 골든셋을 고칠 필요가 없습니다.
- `coverage=partial`: 질문의 일부만 데이터로 답할 수 있음. 빠진 부분은 target_answer에 "(… 데이터에 없음)"으로 적었습니다.
- `python rag/evaluate.py check`: 정답 위치와 근거 구절 검수 + 검토지 `golden_review.md` 생성
- `python rag/evaluate.py vector|bm25|hybrid`: 검색 방식별 평가 → `data/rag/eval_results/{방식}.json` (검색 코드는 `rag/search.py`)

아래 표는 79문항·finlife 포함 시점의 비교입니다.

| 방식 | 전체 Hit@1 | 전체 Hit@5 | G Hit@1 | R Hit@1 | R Hit@5 | R MRR |
|---|---|---|---|---|---|---|
| **vector** (Gemini) | **0.784** | **0.959** | **0.967** | **0.659** | **0.932** | **0.767** |
| bm25 (Kiwi 형태소) | 0.405 | 0.703 | 0.567 | 0.295 | 0.614 | 0.423 |
| hybrid (RRF k=60, 후보 20) | 0.703 | 0.878 | 0.833 | 0.614 | 0.818 | 0.682 |
| hybrid, 벡터 가중치 2배 | 0.703 | 0.905 | 0.833 | 0.614 | 0.864 | 0.697 |
| hybrid, BM25 명사만 | 0.595 | 0.838 | 0.667 | 0.545 | 0.773 | 0.630 |

R 세부 (vector): 완전 답변 n=20 Hit@1 0.850 / Hit@5 0.950, 부분 답변 n=24 Hit@1 0.500 / Hit@5 0.917

**결론: 벡터 단독을 씁니다.** BM25가 너무 약해서 RRF로 섞으면 오히려 벡터 순위를 끌어내립니다.
실제 질문은 "통장 빌려주면", "모르는 돈"처럼 문서(법·약관)와 단어가 달라서 단어 일치 검색이 잘 맞지 않습니다.
이전 프로젝트에서는 하이브리드가 이겼는데, 여기서는 질문이 구어체라 결과가 달라진 것으로 추정합니다 (따로 검증하지 않음).
하이브리드 변형 두 개(가중치 2배, 명사만)는 스크래치 실험이라 코드에 넣지 않았습니다.

직접 쓴 질문(G)은 FAQ와 같은 사람이 써서 점수가 부풀려집니다. 실제 질문(R) 점수를 기준으로 비교하세요.
### 빈 데이터 채운 뒤 (2026-11-05, 벡터)
| 묶음 | n | Hit@1 | Hit@5 | MRR |
|---|---|---|---|---|
| 전체 | 85 | 0.847 | 0.965 | 0.893 |
| 직접 작성 G | 30 | 0.900 | 1.000 | 0.942 |
| 실제 질문 R 전체 | 55 | 0.818 | 0.945 | 0.867 |
| 기존 R01~R44만 | 44 | **0.773** (전 0.659) | 0.932 | 0.833 (전 0.767) |
| 새 R45~R55 | 11 | 1.000 | 1.000 | 1.000 |

- 공정 비교는 기존 R01~R44 줄입니다. 새 문항은 새 FAQ에 맞춰 넣은 것이라 쉽습니다.
- 새 청크가 1위를 가져간 질문 중 새 청크도 정답인 4개(G18, R12, R35, R42)는 정답 위치를 추가했습니다. 정답이 아닌데 밀린 질문(G04, R17)은 그대로 두었습니다.
- 여전히 놓침: R09(이의제기 조항), R37(지연배상금), R38(타행 주담대 상품이 상위 차지).

## 실제 고객 질문 후보 (`golden_candidates.csv`)
Q&A 사이트 아하(a-ha.io)에서 실제 사람들이 올린 은행 질문 62개를 모았습니다. 네이버 지식iN은 검색에 잡히지 않고 브라우저 접근도 막혀 아하로 대신했습니다.
- 열: `id, topic, question(원문 제목), source_url, style(구체/모호), answerable_now(Y/부분/N), source_or_gap`
- 현재 데이터로 답변 가능 20 / 부분 24 / 불가 18, 구체 31 / 모호 31
- 골든셋에 옮길 때는 정답 위치(targets)와 근거 구절을 붙이고 `python rag/evaluate.py check`로 검수합니다.

착오송금 반환지원 상한은 5천만원 → 1억원으로 바뀌어(찾기쉬운 생활법령정보) 내금고 FAQ와 골든셋 G03을 고치고, 낡은 예보 FAQ CSV의 '대상 금액' 문항은 청크에서 뺐습니다.
