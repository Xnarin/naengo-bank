# 소비 분석·잔액 예측·정기결제 후보

기존 LangGraph의 ACCOUNT_QUERY 도구 루프에 읽기 전용 도구 3개를 추가했다. 사용자 ID는 인증된 세션의 클로저로 고정한다. LLM은 기간과 도구를 고르고 설명하며, 금액·증감·평균·예측·후보 탐지는 `backend/app/services/insights.py`에서 계산한다. 계산 결과에 없는 숫자·비율·절약 목표는 생성하지 않도록 지시한다.

| 도구 | 계산 |
|---|---|
| `spending_analysis(month?)` | 최근 12개월 중 월별 출금, 카드 소비와 이체 분리, 분류별 금액·증감. 이번 달은 전월 같은 일자까지 비교 |
| `balance_forecast(month?)` | 이번 달·다음 달 지출 및 월말 잔액·부족액·하루 출금 예산 |
| `detect_subscriptions()` | 최근 180일에서 같은 가맹점의 월 정기결제 후보. 최소 3회, 25~35일 간격, 금액 차이 10% 이내 |

원장을 기준으로 카드 결제를 한 번만 합산한다. 해지한 내 계좌의 과거 내역도 포함하며, 내 계좌 사이의 이동은 제외한다. 외부 계좌이체는 용도가 확정되지 않은 출금으로 따로 표시한다.

예측의 변동 출금은 완료된 전날까지 최대 90일간의 일평균을 사용한다. 자동·예약이체와 정기결제 후보는 평균에서 빼고 예정일에 별도로 반영해 이중 계산을 막는다. 등록 이체는 서비스의 실제 주기 계산을 재사용한다. 미래 입금은 0원으로 가정하고, 월말 잔액은 현재 총잔액에서 남은 기간 예상 출금을 차감한다. 금액은 정수 원 단위이며 나눗셈은 올림한다.

최소 28일과 출금 5건이 없으면 예측 금액을 반환하지 않는다. 전체 출금 범위는 변동 출금 ±20%에 예정 지출을 더한 시나리오이며 통계적 신뢰구간이 아니다. 미래 급여·일회성 지출·구독 취소·외부 은행 내역은 확정하지 않는다. 구독 후보를 자동 해지하지 않는다.

## 검증

화면용 블록은 `app/agent/insight_blocks.py`에서 계산 도구의 원본 결과로 만든다. LLM의 문장을 분석해 차트 값을 추출하지 않는다. 소비는 선택 가능한 도넛·전월 비교 막대, 예측은 날짜 슬라이더가 있는 일별 잔액 선 그래프, 정기결제 후보는 월 합계와 서비스별 카드로 표시한다. 일별 잔액도 Python에서 계산하며 마지막 점은 월말 예상 잔액과 일치한다. 예측 기록이 부족하면 가짜 선 그래프를 그리지 않는다.

- `node tests/insight-cards.mjs`: 음수·평평한 곡선, 데이터 부족, 빈 소비, 구독 금액의 화면 렌더링 검사.
- `uv run pytest -q tests/test_agent_visuals.py`: 서버 블록·계산 수치 일치, 소유자 데이터 사용, 오류·후속 답변에 이전 차트가 섞이지 않는지 검사.

- `uv run pytest -q tests/test_insights.py`: 집계·자기계좌 제외·소유자 범위·반복결제·말일·예정이체·데이터 부족·부족액 검사.
- `uv run python -u -m app.agent.evaluate insights`: 실제 모델이 계산 도구를 호출하고 숫자와 데이터 부족 조건으로 답하는지 검사. 결과는 `data/rag/eval_results/agent_flows.json`.
- 기존 에이전트 업무 흐름 19개와 보안 10개도 실제 모델로 검사했다.

## 개발 계정 체험

사용자가 요청한 test1 계정에만 2026년 8~10월 가상 이력을 넣었다. 메모는 `가상 분석데이터 v1`이다. 월 입금·출금을 맞춰 기존 잔액과 거래를 유지했고 test2는 수정하지 않았다. StreamFlix·CloudMusic·CloudDrive가 월 정기결제 후보로 탐지된다. 현재는 실제 학습 모델의 장기 예측 정확도나 실서비스 데이터로 검증한 예측이 아니다.
