# 자동이체 출금 계좌 선택 반복 문제

2026-11-11, 운영 화면에서 출금 계좌 버튼을 눌러도 “어느 계좌에서 보낼까요?”가 반복된다는 제보.

## 원인과 수정

기존 버튼은 계좌 이름에 “에서”를 붙인 문장을 보냈다. 요청 분류와 출금 계좌 추출을 매번 모델에 맡겨 선택 결과가 보장되지 않았다. 계좌 이름이 같으면 버튼 자체로도 구분되지 않았다.

출금 계좌 선택 단계에서는 버튼의 정확한 계좌번호를 서버가 읽고 본인 소유·정상 상태·받는 계좌와 다름을 검사한다. 이 단계의 버튼 선택에는 모델을 호출하지 않는다. 화면에는 계좌 이름과 마스킹 번호를 함께 표시한다. 이전 화면의 이름만 있는 버튼도 사용 가능한 본인 계좌 한 개와 정확히 일치하면 처리한다. 금액, 받는 계좌와 자동이체 조건은 유지하고 기존 PIN 승인으로 진행한다.

## 검증과 한계

- 회귀 테스트: 일반 송금/자동이체 각각 새 버튼과 이전 버튼으로 다음 확인 화면에 도달한다. 모델 호출은 금지하는 대역으로 검사한다.
- 같은 별칭의 계좌도 새 버튼으로 구분한다. 타인·없는·정지된 계좌는 선택되지 않는다.
- 실제 Gemini 3.5 Flash-Lite 평가: 대표 계좌를 해제한 가상 계정에서 자동이체 새 버튼, 자동이체 이전 버튼, 일반 송금 새 버튼의 3건 모두 통과했다. 받는 계좌·금액·주기·출금 계좌를 확인했고 송금과 자동이체 등록은 0건이었다.
- 결과: `data/rag/eval_results/runs/20261111-093535-source-loop-gemini-3.5-flash-lite.json`.
- 제보자의 운영 대화 원본은 조회하지 않았다. 수정 전 실제 모델의 같은 흐름은 한 번 정상 통과했으므로 화면의 반복을 매번 재현했다고 보지는 않는다. 모델 해석에 의존하던 경로를 제거한 회귀 검증이다.

운영에서는 실제 송금이나 자동이체를 등록하지 않는다. 배포 후에는 새로고침하고 새 대화에서 확인한다. 서버 재시작으로 기존 대화의 진행 상태가 사라질 수 있다.
